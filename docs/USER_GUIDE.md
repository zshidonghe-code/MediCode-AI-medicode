## 系统概述

**码医 MediCode** 是一个 AI 驱动的医疗 DRG 编码与病历质量控制系统，帮助医院实现：

| 能力 | 说明 |
| --- | --- |
| **智能编码** | NLP 解析病历，自动匹配 ICD-10 诊断编码和 ICD-9-CM-3 手术操作编码 |
| **DRG 分组** | 基于国家医保局 CHS-DRG 1.2 版分组方案，自动计算 DRG 权重和预估支付金额 |
| **病历质控** | 100+ 预定义规则检查，覆盖完整性、逻辑一致性、编码一致性、规范表达等维度 |
| **运营分析** | CMI、平均住院日、费用消耗指数、质控合格率等关键指标的实时看板 |

适用场景：

- 病案室编码员日常编码辅助
- 临床医生出院小结质控自查
- 医保办 DRG 分组核对与费用预估
- 院领导数据决策与科室绩效分析

```
 病历文本 ──> NLP解析 ──> ICD编码 ──> QC质控 ──> DRG分组 ──> 预估支付
   |             |            |           |            |            |
   | 出院小结    | 诊断实体    | ICD-10    | 完整性检查  | MDC大类     | ¥预估金额
```

## 快速入门：5分钟上手

### 第一步：登录系统

打开浏览器访问 `http://localhost:5173`，使用演示账号登录：

| 角色 | 用户名 | 密码 | 适用场景 |
| --- | --- | --- | --- |
| 管理员 | `admin` | `123456` | 所有功能、数据管理 |
| 编码员 | `coder` | `123456` | 编码、质控操作 |
| 医生 | `doctor` | `123456` | 编码、质控操作 |

### 第二步：进入流水线工作台

登录后点击左侧菜单 **"流水线"**，你会看到：

- 左侧：病历文本输入区
- 右侧：四步流程状态（编码 -> 质控 -> 分组 -> 支付）

### 第三步：加载示例病例

点击输入区上方的示例病例按钮（**心内科 · 急性心肌梗死** / **呼吸科 · COPD急性加重** / **骨科 · 股骨颈骨折**），系统会自动填充一份完整的出院小结。

### 第四步：点击播放

点击 **"开始分析"** 按钮（或播放图标），系统会自动执行：

1. **NLP 解析**：分词、实体识别、SOAP 结构化
2. **ICD 自动编码**：匹配诊断和手术编码，选择主要诊断
3. **质控检查**：内置质控规则扫描，定位缺陷
4. **DRG 分组**：落组、计算权重和预估支付金额

整个流程约 3-10 秒（无 LLM 时更快）。

### 第五步：查看结果

结果区域会展示：

- **诊断编码**：主要诊断 + 次要诊断 + 手术操作，每条含编码、名称、置信度
- **质控打分**：质控评分（100 分制），缺陷按严重级别列表
- **DRG 分组**：MDC -> ADRG -> DRG 编码，权重和预估支付金额
- **费用测算**：DRG 预估支付金额

点击 **"保存结果"** 可将全链路数据保存到数据库，供仪表盘分析。

### ICD 编码搜索

点击 **"搜索编码"** 按钮打开搜索对话框。

**搜索方式**：

| 输入类型 | 示例 | 说明 |
| --- | --- | --- |
| 中文关键词 | `高血压` | 精确匹配诊断名称 |
| ICD 编码 | `I10` | 按编码前缀搜索 |
| 拼音首字母 | `gxy` | 拼音码搜索 |
| 模糊匹配 | `心肌` | 语义搜索相关诊断 |

**搜索结果**：

每行显示：
- ICD 编码（如 `I10.x00`）
- 编码名称（如 `原发性高血压`）
- 匹配度评分（0-1）

### 编码逻辑说明

系统在自动编码时会进行以下智能处理：

1. **主要诊断选择**：
   - 急性/危重诊断优先（如心梗 > 高血压）
   - 手术科室相关诊断加权
   - 症状编码（R 码）降权
   - 慢性稳定疾病降权

2. **次要诊断过滤**：
   - 去重：同编码保留最高置信度
   - 冲突检测：排除"急性心梗 + 陈旧性心梗"等矛盾编码
   - 同大类过滤：排除主要诊断的子类编码
   - 结果上限：最多保留 9 条次要诊断

3. **编码校验**：
   - 性别冲突：男性不走女性特有编码（如 N70.x 卵巢疾病）
   - 主次逻辑：Z 码不作为主要诊断

### 文件上传解析

支持上传 `.txt`、`.docx`、`.pdf` 病历文件。上传后自动解析文本内容，显示解析统计（文本长度、页数、识别出的诊断数和手术数）。解析完成后需手动点击"开始编码"。

### 输入说明

| 字段 | 格式 | 示例 | 必填 |
| --- | --- | --- | --- |
| 主要诊断编码 | 单个 ICD-10 编码 | `I21.300` | 是 |
| 次要诊断编码 | 逗号/空格分隔 | `I10.x00, E11.900` | 否 |

### 编码输入提示

- 编码支持逗号（`,`）、中文逗号（`，`）、空格分隔
- 可以从流水线工作台或编码工作台的编码结果中直接复制
- 编码格式：ICD-10 诊断编码如 `I21.300`，ICD-9-CM-3 手术编码如 `36.0700`

### 分组结果解读

**MDC（主要诊断大类）**：

系统包含 26 个 MDC 大类，涵盖：

| MDC | 名称 | 代表编码前缀 |
| --- | --- | --- |
| MDCA | 神经系统疾病 | G00-G99, C70-C72 |
| MDCB | 眼科疾病 | H00-H59 |
| MDCC | 耳鼻喉疾病 | H60-H95 |
| MDCD | 呼吸系统疾病 | J00-J99 |
| MDCE | 循环系统疾病 | I00-I99 |
| MDCF | 消化系统疾病 | K00-K64 |
| MDCG | 肝胆胰疾病 | K70-K87 |
| MDCH | 骨骼肌肉疾病 | M00-M99 |
| MDCI | 皮肤疾病 | L00-L99 |
| ... | ... | ... |

**DRG 编码规则**：

```
DRG编码 = ADRG编码 + 合并症后缀

后缀含义:
  1 = 伴严重并发症或合并症 (MCC)
  3 = 伴一般并发症或合并症 (CC)
  5 = 不伴并发症或合并症
  9 = 未分组
```

**费用计算**：

```
预估支付金额 = DRG相对权重(RW) x 基础费率

基础费率由医保局设定，系统中默认为 ¥12,000（可通过 DRG_BASE_RATE 环境变量配置）
```

### DRG 对比功能

点击右上角 **"对比"** 按钮，可以输入人工分组编码，系统自动计算差异：

```
AI分组:  FM11  权重: 3.45  预估: ¥41,400
人工分组: FM13  权重: 1.82  预估: ¥21,840
差异:  ¥19,560
```

## 质控中心

质控中心提供独立的病历内涵质控功能，适合质控人员进行病历质量审核。

### 页面布局

```
+------------------------------------------+------------------------------------------+
|          病历输入区                         |          质控结果                         |
|                                          |                                          |
|  [录制类型选择: 出院小结]                  |  质控评分: [86 / 100] ======             |
|                                          |                                          |
|  +------------------------------------+  |  统计:                                   |
|  |                                    |  |    严重: 0   重要: 1   一般: 2   提示: 0 |
|  |   病历文本输入框                     |  |                                          |
|  |                                    |  |  筛选: [严重级别▼] [规则类型▼]           |
|  +------------------------------------+  |                                          |
|                                          |  +------------------------------------+  |
|  [开始质控]                              |  |  缺陷列表                            |  |
|                                          |  |  [QC-001] [严重] 出院小结完整性       |  |
|                                          |  |  建议: 出院小结必须包含出院诊断       |  |
|                                          |  +------------------------------------+  |
+------------------------------------------+------------------------------------------+
```

### 质控维度

系统从 6 个维度进行病历质量检查：

| 维度 | 代号 | 检查内容 | 示例规则 |
| --- | --- | --- | --- |
| 完整性 | `completeness` | 必填字段、必含章节 | 出院小结必须包含出院诊断 |
| 逻辑一致性 | `logic` | 前后矛盾、时间冲突 | 入院日期不能晚于出院日期 |
| 编码一致性 | `coding` | 编码与文本相互验证 | 诊断编码应与文本描述一致 |
| 时效性 | `timeliness` | 记录完成时间 | 出院小结应在出院后 24h 内完成 |
| 规范表达 | `normalization` | 术语规范、格式正确 | 药品名称应使用通用名 |
| 语义质量 | `semantic` | LLM 语义分析 | 诊断与治疗方案的逻辑协调性 |

### 评分机制

```
初始分: 100

扣分规则:
  严重缺陷 (critical): 每个 -10 分
  重要缺陷 (major):    每个 -5 分
  一般缺陷 (minor):    每个 -2 分
  提示信息 (info):     每个 -0.5 分

最终分 = max(0, 100 - 总扣分)
```

### 缺陷严重级别判定

| 级别 | 颜色 | 含义 | 示例 |
| --- | --- | --- | --- |
| 严重 | 红色 | 医保拒付风险，必须立即修正 | 主要诊断缺失、性别编码错误 |
| 重要 | 橙色 | 影响 DRG 分组准确性 | 出院小结缺少诊疗经过 |
| 一般 | 金色 | 一般性缺陷 | 辅助检查结果未摘要 |
| 提示 | 蓝色 | 建议性意见 | 术语规范建议 |

### 筛选过滤

使用筛选栏快速定位特定类型的缺陷：

- **严重级别筛选**：严重 / 重要 / 一般 / 提示（可多选）
- **规则类型筛选**：完整性 / 逻辑一致性 / 编码一致性 / 时效性 / 规范表达 / 语义质量（可多选）

### 质控结果操作

每条缺陷支持：

| 操作 | 说明 |
| --- | --- |
| **采纳** | 确认缺陷有效，记录修改 |
| **驳回** | 标记为误报，可供规则优化参考 |

点击缺陷行可查看详情：规则 ID、规则名称、缺陷文本片段、修改建议。

### 指标解读

**CMI（病例组合指数）**：

```
CMI = Σ(各病例DRG权重) / 总病例数
```

- CMI > 1.0：医院收治病例复杂度高于平均水平，多为三级医院
- CMI = 1.0：处于平均水平
- CMI < 1.0：收治病例相对简单

**费用消耗指数**：

```
费用消耗指数 = 例均费用 / (基础费率 x CMI)
```

- > 1.0：费用超支，可能存在过度医疗或编码不足
- < 1.0：费用结余，效率较高

**时间消耗指数**：

```
时间消耗指数 = 实际平均住院日 / (RW x 3.5)
```

- > 1.0：住院时间超长，效率低
- < 1.0：住院效率高

## 常见问题 FAQ

### 编码相关

**Q: 为什么系统给出的编码和我想的不一样？**

A: 系统遵循 CHS-DRG 1.2 分组方案的主要诊断选择原则：急性/危重优先、手术科室相关诊断加权、合并症降权。如果你认为编码有误，可以：
1. 查看编码置信度，低置信度的结果建议人工复核
2. 使用"搜索编码"功能查找正确的 ICD 编码
3. 在 DRG 页面使用"对比"功能比较不同编码的分组结果

**Q: 编码结果中的"主要诊断"是怎么选出来的？**

A: 系统综合考虑以下因素：
1. 诊断与手术操作的相关性（如心内科手术会提升心脏相关诊断的优先级）
2. 急性 vs 慢性诊断（急性条件加权 +0.40）
3. 排除不应作为主要诊断的编码（如 Z 码、症状 R 码、产科 O 码）
4. 主要诊断与次要诊断的冲突检测

**Q: 为什么有些诊断被排除了？**

A: 系统自动排除：
- 产科相关编码（O 码），除非确实为产科病例
- 糖尿病并发症子类编码（E11.2-E11.7），避免与基础编码重复
- 与主要诊断同大类、且为子类的编码
- 相互冲突的诊断（如"急性心梗"和"陈旧性心梗"不会同时出现）

### DRG 相关

**Q: DRG 预估支付的金额准确吗？**

A: 预估支付 = DRG 权重 (RW) x 基础费率。基础费率由各地医保局设定，系统默认值为 ¥12,000。请根据你所在地区的实际费率修改 `.env` 文件中的 `DRG_BASE_RATE` 值。

**Q: 为什么同一个诊断，不同的手术会有不同的 DRG？**

A: DRG 分组首先判定是否为"手术组"。有手术操作编码的病例通常进入手术组，且手术类型直接决定 ADRG 分组。无手术操作的进入内科组，分组结果主要取决于主要诊断和合并症。

**Q: CC/MCC 是怎么判定的？**

A: 系统通过次要诊断编码列表判定合并症级别。MCC（严重合并症/并发症）和 CC（一般合并症/并发症）会影响最终的 DRG 后缀（1/3/5），进而影响权重和支付金额。

### 质控相关

**Q: 质控评分的扣分规则是什么？**

A: 满分 100 分。严重缺陷每条 -10，重要缺陷每条 -5，一般缺陷每条 -2，提示每条 -0.5。最低分 0 分。评分超过 90 分视为合格。

**Q: 为什么质控检查报告没有错误？**

A: 如果文本内容非常简短或格式不规范，部分规则（特别是逻辑一致性和编码一致性）可能无法有效触发。建议使用完整的出院小结格式进行质控，包含：主诉、现病史、既往史、查体、辅助检查、诊断、治疗经过等章节。

**Q: LLM 语义检查是什么？**

A: 当开启 LLM 模式（`use_llm: true`）时，系统会将病历文本发送给大模型进行深度语义分析，检查诊断与治疗方案之间的逻辑协调性。默认关闭以保证响应速度和数据隐私（无 LLM 时仅运行规则检查）。

### 系统相关

**Q: 不需要装 GPU 也能跑吗？**

A: 可以。Ollama LLM 是可选组件。不装 Ollama 时，系统使用纯规则引擎和向量搜索，编码和质控功能完全正常。LLM 仅作为精度增强手段。

**Q: 病历数据安全吗？**

A: 系统设计为本地部署架构，所有数据存储在本地 SQLite/PostgreSQL 数据库中。LLM 推理使用本地 Ollama（Qwen2.5），数据不会发送到外部服务器。患者姓名使用 SHA-256 哈希存储，实现匿名化。

**Q: 如何添加更多的 ICD 编码或质控规则？**

A:
- **ICD 编码**：编辑 `backend/src/data/icd_diagnoses.json` 和 `backend/src/data/icd_procedures.json` 文件，添加新的编码条目（含别名）
- **质控规则**：在 `backend/src/services/qc_engine/engine.py` 的 `_build_default_rules` 方法中添加新的规则字典
- 修改后重启后端服务即可生效

**Q: 支持哪些病历类型？**

A: 系统 NLP 引擎支持解析以下病历类型：
- `admission` 入院记录
- `discharge` 出院小结
- `surgery` 手术记录
- `course` 病程记录
- `consultation` 会诊记录
- `exam` 检查报告
- `lab` 检验报告

其中**出院小结**和**入院记录**的 NLP 解析效果最佳。

**Q: 系统对性能有什么要求？**

A: 推荐配置见[部署指南](./DEPLOY.md#环境要求)。基础功能（规则引擎 + 向量搜索）在 4 核 8GB 机器上即可流畅运行。如需启用 Ollama LLM，建议 16GB+ 内存。

**Q: 遇到问题如何反馈？**

A: 查看后端日志（控制台输出）获取详细错误信息。常见问题请参考[部署指南 FAQ](./DEPLOY.md#常见问题)。
