## 1. 测试方法

### 1.1 测试流程

基准测试脚本 `tests/benchmark_accuracy.py` 直接调用编码引擎（无需运行服务器），完整复现生产管线：

```
原始病历文本 → NLP结构化解析 → 诊断/手术实体提取 → ICD编码推荐 → 主要诊断选择（急重症加分逻辑）→ 编码去重
```

该流程与 API 端点 `/api/v1/coding/auto-code` 的逻辑完全一致。

### 1.2 测试集构成

基准测试集为 **4 份金标准病历**（硬编码于脚本 `TEST_CASES`），覆盖循环、呼吸、骨科三大临床领域：

| 编号 | 病例名称 | 科室 | 预期主诊断 | 预期手术编码 |
|------|----------|------|-----------|-------------|
| CASE-01 | AMI+PCI | 循环/心血管 | I21.900 急性心肌梗死 | 36.0700 药物洗脱支架植入 |
| CASE-02 | COPD/慢阻肺 | 呼吸科 | J44.900 慢性阻塞性肺疾病 | (无) |
| CASE-03 | 髋部骨折 | 骨科 | S72.900/S72.000 股骨骨折 | 81.5100 全髋关节置换 |
| CASE-04 | 社区获得性肺炎 | 呼吸科 | J18.900 肺炎 | (无) |

编码引擎使用 `src/data/icd_diagnoses.json` 和 `src/data/icd_procedures.json` 中的本地索引（920条诊断编码，含别名索引约7,600术语 + 611条手术编码，含别名索引约4,400术语）。本次测试关闭LLM辅助功能，仅测试规则引擎。

> **样本量声明**：4 例仅用于验证编码链路的正确性，不满足任何统计显著性要求，
> 不能据此宣称或推算生产准确率。建立经医学专家审核的标准病例集（30-50 例起步）
> 是当前最高优先级事项，见 `docs/COMPETITION_2027_PLAN.md` 阶段二。

## 2. 准确性测试结果

### 2.1 当前执行结果（2026-09-06，含当日修复）

```
==============================================================================
  BENCHMARK RESULTS SUMMARY
==============================================================================
  Primary diagnosis accuracy : 4/4  (100.0%)
  Procedure code accuracy    : 4/4  (100.0%)
  Overall accuracy (both)    : 4/4  (100.0%)
==============================================================================
```

4 例全过建立在当日两处真实修复之上（commit 1914b11）：

1. **手术实体抽取**：原 `SURGERY_PATTERNS` 只匹配以「术」结尾的词，「药物洗脱支架」无法抽出；且本地索引别名先到先得使 36.0600 独占共用别名「PCI术」。现新增支架类型词表（`STENT_TYPES`），并引入特异码优先规则（36.07 出现时移除泛化的 36.06）。
2. **否定检测**：否定词表原缺「无」，「无高血压、糖尿病史」被当作真实诊断参与主诊断竞争（CASE-02 主诊断因此误选糖尿病）。现补齐该词并限定否定作用域为实体前最后一个分句，避免「无发热，咳嗽明显」这类跨句误伤。

### 2.2 历史结果存档（修复前，2026-09-06 上午实测）

```
Primary diagnosis accuracy : 3/4  (75.0%)
Procedure code accuracy    : 3/4  (75.0%)
Overall accuracy (both)    : 2/4  (50.0%)
Status: BELOW human baseline
```

失败细节：CASE-01 手术编码 36.0700 被匹配为泛化的 36.0600；CASE-02 主诊断被 E14.900（糖尿病）抢占。

## 3. 与质控缺陷发现能力基准的关系

编码准确率受限于金标准缺失，本项目另行建立了**注入式缺陷基准**（不需要医学专家标注金标准）评估质控引擎的缺陷发现能力：

- 400 份合成病历（340 份注入已知缺陷 + 60 份干净对照），随机种子固定，完全可复现
- 缺陷召回率 100%（17/17 条规则全部触发）
- 干净病历误报率 21.7%（根因已定位：编码引擎手术候选过宽）

详见 `docs/QC_BENCHMARK_REPORT.md`。

## 4. 已知限制

1. 4 例样本量无法支撑任何准确率宣称，结果仅证明编码链路在该 4 类病例上工作正常。
2. 人工编码员准确率（约 85-90%）引自公开文献统计，仅作背景参考，不构成与 4 例小样本的可比结论。
3. LLM 增强模式的效果需要单独基准测试，本仓库尚未提供可用于宣称的结果。
4. 响应时间在开发机环境测得（约 0.5-1.5 秒/例，首例含引擎初始化），不代表生产部署性能。
