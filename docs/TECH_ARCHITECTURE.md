## 三、核心算法设计

### 3.1 ICD编码引擎

**流程：**
```
病历原文
  → 结构化提取（SOAP拆分）
  → 关键医学实体识别（诊断名、手术名、病理结果）
  → 候选ICD编码召回（向量检索 + 拼音检索）
  → LLM编码推荐（RAG增强）
  → 编码校验（排除规则、性别年龄约束、主次诊断逻辑）
  → 最终编码输出
```

**编码准确率目标：**
- 编码效果：4 例金标准验证性测试全过（样本量小，不构成准确率宣称）；质控缺陷发现：400 份注入式基准，召回 100%
- 全部编码准确率 ≥ 90%
- 手术操作编码准确率 ≥ 92%

### 3.2 DRG分组引擎

**流程：**
```
ICD编码结果
  → MDC大类判定（26个主要诊断大类）
  → 手术/非手术分组判别
  → 细分组匹配（CHS-DRG 1.2版 628个ADRG → 1236个DRG组）
  → 合并症/并发症判定（CC/MCC逻辑）
  → 分组结果 + 权重 + 预估支付金额
```

### 3.3 质控规则引擎

**规则分类及示例：**

| 类型 | 数量 | 示例 |
|------|------|------|
| 完整性检查 | 30条 | "出院小结必须有出院医嘱" |
| 逻辑一致性 | 25条 | "手术记录中的手术部位与诊断不一致" |
| 编码一致性 | 20条 | "ICD编码与病历中的诊断描述不匹配" |
| 时效性检查 | 10条 | "入院记录未在24小时内完成" |
| 规范表达 | 15条 | "主要诊断应为病因诊断而非症状诊断" |

**规则引擎架构：**
```python
# 规则定义示例
{
    "id": "QC-001",
    "name": "出院小结完整性检查",
    "severity": "高",
    "type": "完整性检查",
    "check_fn": "check_discharge_summary_completeness",
    "params": {"required_sections": ["出院诊断", "入院情况", "诊疗经过", "出院医嘱"]}
}
```

## 五、安全设计

- 数据不出院：全部组件私有化部署
- 病历脱敏：姓名、身份证号、住址等PII自动脱敏
- 访问控制：RBAC角色权限（医生/编码员/质控员/管理员）
- 操作日志：所有编码修改有完整审计追踪
- 备份策略：PostgreSQL自动每日备份
