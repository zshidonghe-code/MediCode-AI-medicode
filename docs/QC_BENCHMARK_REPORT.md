**测试日期**: 2026-09-06
**测试脚本**: `backend/tests/benchmark_qc.py`
**病例集**: `backend/tests/fixtures/competition_cases.json`（400 份，随机种子 20260906，完全可复现）
**引擎版本**: MediCode QC Engine 规则层（LLM 语义检查关闭）

## 1. 为什么用注入式缺陷，而不是"准确率"

编码 Top-1 准确率的分母是专家标注的金标准答案，本项目目前没有医学顾问，无法产生可信金标准。而**缺陷发现能力不需要金标准**：缺陷由测试脚本人为注入合成病历，预期答案在注入时就已确定，召回率因此是可严格度量的真指标。

这也与本项目的定位一致：码医是"提交前辅助审核"工具，核心价值是**把缺陷捞出来**，而不是替代编码员做最终判断。

### 1.1 设计原则（保证结果诚实）

1. **底料全部为合成病历**，不含任何真实患者数据。四个科室模板（循环、呼吸、骨科、消化）随机组合生成，姓名、年龄、性别、日期随机化。
2. **缺陷由脚本注入**，与引擎实现相互独立，不存在"自己出题自己考"。
3. **设干净对照组**：60 份无缺陷合成病历。没有对照组的话，一个"见病历就报"的引擎也能拿到 100% 召回。

### 1.2 病例集构成

| 组 | 数量 | 说明 |
|---|---:|---|
| 缺陷组 | 340 | 17 条质控规则 × 每条 20 份，每份注入 1 个已知缺陷 |
| 干净对照组 | 60 | 无注入缺陷，用于测量误报率 |
| **合计** | **400** | |

## 2. 测试结果

```
==============================================================================
  Rule      Injected  Detected    Recall
------------------------------------------------------------------------------
  QC-001          20        20    100.0%
  QC-002          20        20    100.0%
  ...（QC-001 ~ QC-104 共 13 条均为 100%）
  QC-201          20        20    100.0%   ← 修复后（修复前 0%，详见 2.1）
  QC-202          20        20    100.0%
  QC-301/302      20        20    100.0%
  QC-401/402      20        20    100.0%
==============================================================================
  Overall defect recall : 340/340 (100.0%)
  Rule coverage         : 17/17 rules fired at least once
  False positive rate   : 13/60 clean cases flagged (21.7%)
==============================================================================
```

### 2.1 基准暴露并修复的问题

**QC-201 是一条从未生效过的死规则（修复前召回 0%）。**
`_check_code_text_consistency` 用贪婪正则提取诊断名中的关键术语，整个中文病名（如"急性心肌梗死"）被当成一个词，术语数量永远是 1，而触发条件要求 ≥ 2，因此该规则自上线以来从未报出过任何问题。
修复：改为 2 字滑窗部分匹配（"肺炎"命中"社区获得性肺炎"），并排除"急性/慢性/原发/继发/先天"等通用修饰词，避免"急性"在"急性阑尾炎"中造成假命中。修复过程 0% → 35%（首轮滑窗）→ 100%（过滤通用词后）。

**编码引擎存在"手术候选爆炸"，这是 21.7% 误报的主要来源。**
干净手术记录经真实编码链路后，平均返回约 7 个手术编码，其中仅 1 个与实际手术相符，其余如"舌手术""针刺麻醉""口腔手术""手术史""胸外按压"均来自病历中无关词句的误抽。QC-102（手术-诊断一致性）忠实地对这些假编码报了警——**误报的根因在上游编码精度，不在质控规则本身**。

### 2.2 结果解读与限制

- **能宣称的**：在 400 份合成病历上，规则层对 17 类已知缺陷的召回率为 100%，17 条规则全部可被触发；对干净病历的误报率为 21.7%，主要根因已定位。
- **不能宣称的**：这不是临床准确率，不能推广到真实病历；样本为合成数据，缺陷类型与真实编码员错误分布可能不同；LLM 语义检查层未参与本测试。
- 误报率 21.7% 偏高，改进方向明确：收紧手术实体抽取与编码候选过滤（预期可同时提升编码质量与质控误报）。

## 3. 复现方式

```bash
# 生成病例集并运行（首次）
cd backend && .venv/Scripts/python tests/benchmark_qc.py --rebuild

# 复用已生成病例集重跑
cd backend && .venv/Scripts/python tests/benchmark_qc.py
```

随机种子固定为 20260906，`--rebuild` 生成的病例集与报告数字完全一致。病例集 JSON 中每份病历的注入缺陷与编码结果均有记录，可逐例审查。
